# 工作原理

这一份讲「一次出图，数据是怎么流动的」。

## 1. 一次出图的完整链路

    积木列表（token / text / weight）
        |  POST /api/expand
        v
    宏展开：@CAM_BUST -> (upper body close-up:1.25)
        |  权重包成 (text:1.3)；逗号拼接
        v
    结构检查（ir.py）
        |  NO_SUBJECT / NEG_EMPTY / CUP_CONFLICT ...
        v
    graph.build(workflow, params)
        |  替换 {{unet}} {{width}} {{seed}} ... 占位符
        |  按 loras 注入 LoraLoaderModelOnly 链
        v
    POST /prompt  ->  ComfyUI 队列
        |  轮询 /history/{id}
        v
    取图 -> output/prefix_timestamp_s{seed}.png
        |  写 data/recipes.json
        v
    返回前端 -> 画廊 / 配方

## 2. 宏展开（prompts.py）

词库是 data/prompt_lib.json：

    { "tokens": { "@CAM_BUST": "(upper body close-up:1.25)" },
      "notes":  { "@CAM_BUST": "胸像" } }

展开时按 key 长度从长到短替换，避免 @CAM 吃掉 @CAM_BUST。
另外动态注入两个宏：

- @OUTFIT：当前套装（character.json 的 garment_default）的正向；
- @NEG_OUTFIT：所有套装负向的并集。

## 3. 杯子冲突的处理

这是早期最容易翻车的地方：正向要杯子、负向又禁 cup，模型就两边不讨好。

expand 会先判断正向是否在「拿杯子」（holding ... cup 或 @PROP_CUP），
如果是：

1. 丢掉负向里的 @NEG_CUP 块；
2. 再对最终负向文本做一遍 drinkware 词清洗（cup / mug / glass / bottle...）；
3. 在返回的 notes 里说明做了这件事。

## 4. 结构检查（ir.py）

先展开，再判断：

| 代码 | 级别 | 条件 |
| --- | --- | --- |
| NO_SUBJECT | 错误 | 正向没有 girl / character / subject 等 |
| NEG_EMPTY | 错误 | 负向为空 |
| NO_QUALITY_NEG | 警告 | 负向没有 lowres / bad anatomy 等 |
| CUP_CONFLICT | 提示 | 正向拿杯 + 负向禁杯（expand 会自动处理） |
| NO_CAM / NO_LIGHT / NO_OUTFIT | 提示 | 建议补机位 / 光 / 服装 |

错误会阻止出图，警告与提示只展示。

## 5. 工作流占位符（graph.py + workflows/*.json）

workflows/t2i.json 是一份 ComfyUI API 格式的节点图，值里写着占位符：

| 占位符 | 来源 |
| --- | --- |
| {{unet}} {{clip}} {{vae}} {{clip_type}} | config.json 的 model |
| {{positive}} {{negative}} | expand 结果 |
| {{width}} {{height}} | 前端参数 |
| {{seed}} {{steps}} {{cfg}} | 前端参数 |
| {{sampler}} {{scheduler}} | config.defaults |
| {{prefix}} | 前端前缀 |
| {{reference}} {{mask}} {{denoise}} | 图生图 / 重绘 |
| {{loras}} | 前端填的 LoRA 列表 |

替换规则：字符串恰好是 {{key}} 才替换；width/height/seed/steps 转 int，
cfg/denoise 转 float；其余保持字符串。

## 6. LoRA 链注入

如果前端填了 LoRA：

1. 找到 UNETLoader 节点；
2. 依次插入 LoraLoaderModelOnly（node 20、21...），前一个的 model 接后一个；
3. 把所有指向 UNETLoader 的 model 输入改接到链尾。

这样不需要为每个 LoRA 数量准备不同的工作流。

## 7. 与 ComfyUI 的交互（comfy.py）

- 提交：POST /prompt，失败时解析 node_errors 拼成人话；
- 进度：轮询 /history/{id}，没有输出就按预计时间做百分比；
- 取图：/history 返回 images 后复制到 output；
- 释放：POST /free {unload_models, free_memory}；
- 节点检查：GET /object_info，对比 workflow.requires。

## 8. 配方

每张成功出图的记录（data/recipes.json）：

    {
      "ts": 1760000000.0, "mode": "t2i", "seed": 424242,
      "size": [1024, 1536], "steps": 28, "cfg": 5.5, "denoise": 1.0,
      "loras": [{"name": "my-style.safetensors", "weight": 0.7}],
      "positive": "...", "negative": "...",
      "blocks_pos": [...], "blocks_neg": [...],
      "workflow": "t2i"
    }

文件超过 500 条时会按 ts 淘汰最旧的。

## 9. 扩展点

- 加工作流：放一份 JSON 到 station/workflows，写上 requires 与占位符即可；
- 加积木：改 prompt_lib.json，或直接在工作站「词库」页加；
- 换模型：改 config.json 或引擎页表单，不用改代码；
- 加页面：static/index.html 加 section，app.js 加渲染函数，后端加路由。
